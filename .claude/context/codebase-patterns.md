### No shadcn/ui components installed

### TypeScript config
- strict mode ON, noUnusedLocals, noUnusedParameters
- `@/` alias → `src/`
- moduleResolution: bundler

### Key patterns
- Fetch: `apiFetch<ResponseType>('/path', { method: 'POST', body: JSON.stringify(data) })`
- Zustand: `create<StoreType>()((set) => ({ ... }))` pattern
- TanStack Query v5: `useMutation({ mutationFn: async (data) => ... })`
- JSX return type: always `JSX.Element` (see AppShell.tsx)
- NavLink active class via `({ isActive }) =>` callback

### App.tsx restructure needed
Auth routes (/register, /login, /setup, /join) must render WITHOUT AppShell.
Protected routes (/orders, etc.) must use ProtectedRoute wrapper.
New structure:
```tsx
<Routes>
  <Route path="/register" element={<RegisterPage />} />
  <Route path="/login" element={<LoginPage />} />
  <Route path="/setup" element={<QuickSetupPage />} />
  <Route path="/join" element={<JoinPage />} />
  <Route element={<ProtectedRoute />}>
    <Route element={<AppShell />}>
      <Route path="/orders" element={<OrdersPage />} />
      ...
    </Route>
  </Route>
</Routes>
```
AppShell must use `<Outlet />` instead of `{children}` after this restructure.

## audit/10-in-app-notifications — Explorer map (2026-07-25)

### Backend — files that will change
- `src/db/schema.ts` (396 lines) — Drizzle tables. Every table follows
  `tenant_id: uuid(...).notNull().references(() => tenants.id)` + a composite
  `index('<table>_tenant_<x>_idx').on(table.tenant_id, ...)`. Types exported at the
  bottom as `typeof x.$inferSelect` / `$inferInsert`.
- `drizzle/` — 0000..0009 SQL migrations + `meta/_journal.json`. Generated by
  `npm run db:generate` (drizzle-kit). New table ⇒ new `0010_*.sql`.
- `src/app.ts` — every router mounted with `app.route('/path', router)`. Add
  `app.route('/notifications', notifications)`.
- `src/routes/*.ts` — pattern: `new Hono<{ Variables: AppVariables }>()`, per-route
  `authMiddleware`, manual `await c.req.json()` in try/catch → `safeParse` → 400
  `{ error: 'Validation failed' }`. Tenant always from `c.get('tenantId')`.
- `src/services/*.ts` — all DB access; every query `and(eq(x.id, ...), eq(x.tenant_id, ...))`.

### Trigger points — verified locations
| Trigger | Real location | Notes |
|---|---|---|
| New lead / booking | `services/leads.service.ts:30 createLead()` | **Single choke point** for all three sources — `routes/book.ts:100` (booking page), `routes/leads.ts:85` (Zapier webhook), `routes/leads.ts:110` (manual). Hooking the service covers all three; hooking the two routes would duplicate. `createLead` sends **no email today** — the only lead email is the 24h stale-lead nudge in the job. |
| Contract signed | `services/contract.service.ts:237-250` | Loops `users` where `role='owner'` and calls `sendContractSignedNotification` per owner. Has `order.tenant_id` + `order.clientName` in hand. |
| Invoice paid | `services/invoices.service.ts:230 markInvoicePaidFromSession()` | Called from `services/billing.service.ts:117` (Stripe webhook). Guarded by `sql\`status <> 'paid'\`` so replays return null — the natural idempotency point. **Does not currently select `tenant_id`** — `getPaidInvoiceEmailData` (line 209) must add it. |
| 24h move reminder | `jobs/reminder.ts:28 sendDailyReminders()` | Owner-facing in-app equivalent. `sendUncontactedLeadReminders` (line 109) is the *other* job and is already owner-facing by email; not in the task's 4-item list. |

### Reminder job — structural constraint found
`sendDailyReminders` sets `reminder_sent = true` **only after a successful email send**
(deliberate, commented at line 90). With email broken that flag never flips, so a
notification placed after it would never be created — exactly the failure this task
exists to fix. Also `if (!client?.email) continue` (line 64) short-circuits before the
tenant/timezone check. Consequences for implementation:
1. The notification must be created **before** the client-email guard, which requires
   moving the tenant fetch + `getTenantTomorrow` check above that guard. Email behaviour
   is unchanged (same guards, same order of side effects).
2. Because `reminder_sent` can't be relied on, the reminder notification needs its own
   idempotency: skip insert if one already exists for (tenant_id, type, related_id).

### Backend test patterns
- Route tests (`routes/*.test.ts`): `vi.mock` the service module + `../db/index.js` +
  `../lib/env.js` + `../lib/logger.js`, then `await import('./route.js')`, mount on a bare
  `new Hono<{ Variables: AppVariables }>().route(...)`. Auth via `src/test/authContext.ts`
  `setAuthContext()` + `signToken()` → `cookie: token=...`.
- `jobs/reminder.test.ts` uses a hand-rolled `db` fake with a **fixed read sequence**
  (`selectQueue` shift per `.where()`), and asserts WHERE conditions by walking
  `queryChunks`. Adding a `db.insert` there would break it ⇒ notification creation must
  live in its own service module so the test can `vi.mock` it.
- Test names are prefixed with the AC they cover (`'AC1 — ...'`).

### Frontend — files that will change
- `components/shared/AppShell.tsx` (68 lines) — header: logo | `<nav>` NavTabs | `<UserMenu />`.
  Bell goes between nav and UserMenu.
- `components/shared/UserMenu.tsx` — **the dropdown precedent**: `relative` wrapper +
  `useRef` + `mousedown` click-outside `useEffect` + absolutely-positioned panel. There is
  **no popover/dropdown-menu primitive** — `components/ui/` has only badge, button, card,
  input, label, select, sheet, switch, tabs, textarea.
- `hooks/*.ts` — TanStack Query v5. Raw snake_case API shape typed as `RawX` + a `mapX()`
  to camelCase (see `useLeads.ts`). Mutations invalidate by `queryKey`.
- `lib/utils.ts` — has `formatDate` (UTC, calendar dates), `formatTimestamp` (local,
  instants), `formatPhone`, `formatCurrency`. **No relative-time helper** — needs adding.
- `types/index.ts` — `Notification` is a DOM global; the app type must be named
  `AppNotification` to avoid shadowing.

### Deep-link gap (blocks AC3 "navigates to the relevant record")
- `App.tsx` routes are flat: `/orders`, `/invoices`, no `:id` segments.
- `OrdersPage.tsx:51` reads only `?tab=leads`, and does so with `useState(...)` — a
  *one-time* initialiser, so navigating to `/orders?tab=leads` while already on `/orders`
  does not switch the tab. Needs a `useEffect` sync.
- `OrdersPage` has **no** `?order=` handling, even though `contract.service.ts:248`
  already emails `${FRONTEND_URL}/orders?order=${id}` — that link is dead today.
- `InvoicesPage.tsx` selects via local `selectedId` state only, no URL param.
⇒ Wire `?order=<id>` (OrdersPage → OrderDetailSheet) and `?invoice=<id>` (InvoicesPage →
selectedId). Leads link to the existing `/orders?tab=leads`.
